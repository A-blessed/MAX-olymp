# Что поправить во фронтенде

Список после проверки `app.js` на живом бэкенде. Приложение уже работает
на настоящих данных: класс сохраняется, предметы и олимпиады приходят с
сервера. Ниже — то, что осталось.

Порядок примерно по важности.

---

## 1. Убрать свой слой API, взять `api.js`

**Где:** `app.js`, строки 65–170 — `const API`, `async function api()`,
`const Api = {…}`, `apiGetMe()`, `apiGetMeSettings()`.

`api.js` подключён в `index.html` и создаёт глобальный `Api`. Но в
`app.js` объявлен **свой** `const Api`, и он перекрывает глобальный:
проверено в браузере, `Api !== window.Api`.

Своя обёртка работает, но не покрывает три случая:

| Что | Чем кончится |
|---|---|
| `DELETE` отвечает `204` с пустым телом, а в обёртке безусловный `response.json()` | «Удалить из моих олимпиад» упадёт с ошибкой разбора |
| Ошибка приходит без кода | Не отличить «лимит трёх в день» от «этап заблокирован» — а вся логика различается именно по коду |
| Адрес бэкенда записан в двух местах | При переезде на хостинг поправят одно, забудут другое |

**Что сделать:** удалить из `app.js` строки 65–170 целиком. Имена методов
почти совпадают, вызовы менять не придётся. Проверить, что осталось:

```js
console.log(Api === window.Api); // должно быть true
```

Заодно `api.js` принимает и `subjectId`, и `subject_id` — сейчас в
`app.js` встречаются оба написания, и одно из них молча отключало фильтр.

## 2. Счётчик «N олимпиад» на экране предметов

**Где:** `app.js`, строка 278 — `${counts[s.id] || 0} олимпиад`.

Сейчас число считается на клиенте из `state.catalogOlympiads`, а там
лежит **одна страница каталога — 50 записей из 220**. Поэтому
«Астрономия: 0 олимпиад», хотя для шестиклассника она одна.

**Что сделать:** взять готовое число с сервера.

```js
const subjects = await Api.catalog.subjects(state.settings.grade);
// у каждого: { id, name, color, short_code, olympiad_count }
```

Один лёгкий запрос вместо выкачивания каталога ради цифр. И `color` со
`short_code` оттуда же — константу `SUBJECTS` из `app.js` можно удалить,
иначе цвета разъедутся с базой при первой же правке справочника.

## 3. Детальная карточка показывает заглушки

**Где:** `app.js`, блок отрисовки карточки, строка 374 и раздел
«ОРГАНИЗАТОРЫ».

У «Бельчонка» показываются организаторы «НИУ ВШЭ / МГУ» и ссылка
`olymp.hse.ru`. В базе у него совсем другое: организаторов нет вообще, а
сайт — `dovuz.sfu-kras.ru/belchonok`. Значит блок рисуется по зашитым
данным.

Проверено: `state.selectedOlympiad` в этот момент пустой объект.

**Что сделать:** сохранять ответ и рисовать из него.

```js
const olympiad = await Api.catalog.get(id);
state.selectedOlympiad = olympiad;
```

| Показать | Поле |
|---|---|
| Организаторы, до трёх | `organizers_list` — уже готовый массив |
| Ссылка на сайт | `official_url` |

## 4. Сортировка и поиск — локально

Решение делать это на клиенте принято, аргументы понятны: запрос на
каждую букву не нужен, и в офлайне сортировка должна работать.

Но тогда **данные надо загружать целиком**, иначе отсортируется только
первая страница из 50. Для этого подняли потолок:

```js
const data = await Api.catalog.all(state.settings.grade); // limit=500
state.catalogOlympiads = data.items;                       // сейчас 220
```

Дальше искать и сортировать в памяти. Список по одному предмету — не
больше тридцати записей, тормозить нечему.

### Правила сортировки

Повторяют серверные — если разойдутся, список будет прыгать при
переключении между вкладками.

**По сроку (`urgency`)** — ближайший идущий или предстоящий этап:

```js
function urgencyKey(o) {
  const s = o.next_stage;
  // Этап без точной даты в сортировку по сроку не попадает:
  // у «мар 2027» дня нет, и сравнивать нечего.
  if (!s || s.start_precision !== 'day' || !s.starts_on) return '9999-12-31';
  return s.starts_on; // строки ISO сравниваются как даты
}
list.sort((a, b) => urgencyKey(a).localeCompare(urgencyKey(b))
                 || a.name.localeCompare(b.name, 'ru'));
```

В `sortMyOlympiads` (строка 479) ветка `urgency` сейчас пустая — список
остаётся в том порядке, в каком пришёл.

**По уровню (`level`)** — в строке 474 сейчас `a.level - b.level`. Если
уровень не заполнен, получится `NaN`, и порядок поедет. Нужно:

```js
const lv = (o) => (o.level == null ? 99 : o.level); // без уровня — в конец
list.sort((a, b) => lv(a) - lv(b) || a.name.localeCompare(b.name, 'ru'));
```

**По предмету** — `a.subject.name.localeCompare(b.subject.name, 'ru')`.

**Во вкладке «Мои олимпиады»** поверх любой сортировки: записи с
`eliminated: true` всегда уходят вниз — по механике они серые и в конце
списка.

```js
list.sort((a, b) => (a.eliminated - b.eliminated) || выбраннаяСортировка(a, b));
```

### Поиск

Искать по `name` и по `subject.name` — механика обещает «по названию или
предмету».

Если всё же захочется искать запросом к серверу, у `/api/catalog/olympiads`
есть параметр `q`, и он тоже ищет по обоим полям. Тогда обязательно
добавить задержку: отправлять запрос не на каждую букву, а через 300 мс
после последнего нажатия.

## 5. Офлайн-режим

Механика обещает кэш последних 50 просмотренных олимпиад и значок
предупреждения. Загрузка каталога целиком (`Api.catalog.all`) это
упрощает: один ответ можно положить в `localStorage` и показывать, пока
сети нет.

Клиент отдаёт отдельный код для этого случая:

```js
catch (e) {
  if (e.code === 'network_error') {
    // показать кэш и значок «нет сети»
  }
}
```

## 6. Мелочи

**`Api.my.list({ q })`** — поиск по «Моим олимпиадам» на сервере теперь
есть, но при локальном поиске он не нужен.

**Класс пользователя** передаётся как `Api.catalog.list({ grade })` или
`{ class }` — клиент понимает оба. Фильтр работает: класс 2 — 36
олимпиад, класс 7 — 125, класс 10 — 220.

**Ошибки** приходят как `ApiError` с полем `code`. Полный список — в
`api-for-frontend.md`. Ветвиться нужно по `code`, а `message` написан
для пользователя и его можно показывать как есть.

---

## Как проверить, что всё сошлось

1. `Api === window.Api` возвращает `true`;
2. на экране предметов числа не нулевые и меняются при смене класса;
3. в карточке «Бельчонка» ссылка ведёт на `dovuz.sfu-kras.ru`, а блока
   организаторов нет;
4. удаление из «Моих олимпиад» не роняет консоль;
5. сортировка по уровню не ставит олимпиады без уровня в начало.
