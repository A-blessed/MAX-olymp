# Как открыть приложение внутри MAX

Три шага, все одноразовые. Держать что-то включённым на машине
разработчика больше не нужно: решение живёт на постоянном домене
`my-olymp.ru`.

Развёртывание самого сервера описано отдельно, в
[deploy-my-olymp.md](deploy-my-olymp.md). Здесь — только то, что касается
запуска внутри мессенджера.

---

## 1. Убедиться, что домен отвечает

Мини-приложение и API отдаются с одного адреса:

```bash
curl https://my-olymp.ru/health
curl -I https://my-olymp.ru/
```

Первое должно вернуть `{"status":"ok", ... "bot_configured":true,
"webhook_secret_set":true}`, второе — `200` и `text/html`.

Требования MAX к адресу: только `https`, до 1024 символов, латиница,
цифры, точка и дефис, без пробелов. `https://my-olymp.ru` им
соответствует.

Открыть адрес можно и в обычном браузере: приложение покажет экран выбора
класса и дальше не пойдёт, потому что `window.WebApp` существует только
внутри мессенджера. Это нормально, главное — страница отдаётся.

---

## 2. Привязать адрес к боту

**Через код это сделать нельзя** — в Bot API такого метода нет, только
через кабинет:

1. Открыть платформу MAX для партнёров, раздел **Чат-боты**;
2. выбрать бота `t654_hakaton_max_bot` → **⋮** → **Настройки**;
3. вставить в поле URL мини-приложения:

   ```
   https://my-olymp.ru
   ```

4. выбрать вид кнопки — «Открыть», «Старт», «Играть» или без названия;
5. **Сохранить**.

После этого в чате с ботом появится кнопка запуска.

**Важно:** токен бота выдали организаторы, значит бот заведён в их
кабинете. Если доступа к настройкам нет — адрес нужно передать им и
попросить привязать. Это стоит выяснить заранее: без этого шага
приложение в MAX не откроется, сколько бы всё остальное ни работало.

Если в поле осталось старое значение (адрес GitHub Pages), MAX продолжит
открывать старую копию приложения — на сервере это никак не отразится.

---

## 3. Перерегистрировать вебхук

Адрес сменился с туннельного на постоянный, поэтому подписку на события
нужно оформить заново — старая указывает на мёртвый ngrok:

```bash
docker compose -f docker-compose.prod.yml run --rm backend python -m scripts.setup_webhook
docker compose -f docker-compose.prod.yml run --rm backend python -m scripts.setup_webhook --list
```

В списке должна остаться одна подписка, на `https://my-olymp.ru/webhook`.
Как удалить старую — в [deploy-my-olymp.md](deploy-my-olymp.md#4-подписка-на-события-бота).

Затем написать боту в MAX: в логах `docker compose -f
docker-compose.prod.yml logs -f backend` появится событие, а бот ответит
в чат.

## Чего не хватит для календаря

Календарь и новости строятся на датах этапов, а в справочнике олимпиад
дат пока нет — только названия, уровни, классы и описания.

Сейчас даты есть у 20 олимпиад из старой выгрузки парсера, и календарь
показывает только их. Как только даты появятся в основном файле,
календарь наполнится сам: разбор дат, точность, статусы этапов и
правила планирования уже написаны и покрыты тестами.

Так что на вопрос «когда начинать пилить календарь» ответ такой: со
стороны бэкенда он готов, ему нужны данные.
