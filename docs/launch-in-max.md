# Как открыть приложение внутри MAX

Четыре шага. Первые три делаются один раз, четвёртый — перед каждым
показом, пока бэкенд живёт на туннеле.

---

## 1. Выложить фронтенд на HTTPS

Мини-приложение обязано работать по `https://`, иначе MAX его не примет.
Документация платформы прямо называет GitHub Pages среди подходящих
вариантов, а репозиторий у нас уже там.

В репозитории: **Settings** → слева **Pages** → в разделе «Build and
deployment»:

| Поле | Значение |
|---|---|
| Source | Deploy from a branch |
| Branch | `main` |
| Folder | `/ (root)` |

**Save**. Через минуту-две адрес заработает:

```
https://a-blessed.github.io/MAX-olymp/frontend/
```

Проверить просто: открыть эту ссылку в браузере. Приложение покажет
экран выбора класса — снаружи MAX оно дальше не пойдёт, потому что
`window.WebApp` существует только внутри мессенджера. Это нормально,
главное, что страница отдаётся.

Требования MAX к адресу: только `https`, до 1024 символов, латиница,
цифры, точка и дефис, без пробелов. Наш адрес им соответствует.

## 2. Привязать адрес к боту

**Через код это сделать нельзя** — в Bot API такого метода нет, только
через кабинет:

1. Открыть платформу MAX для партнёров, раздел **Чат-боты**;
2. выбрать бота `t654_hakaton_max_bot` → **⋮** → **Настройки**;
3. вставить адрес из шага 1 в поле URL мини-приложения;
4. выбрать вид кнопки — «Открыть», «Старт», «Играть» или без названия;
5. **Сохранить**.

После этого в чате с ботом появится кнопка запуска.

**Важно:** токен бота выдали организаторы, значит бот заведён в их
кабинете. Если доступа к настройкам нет — адрес нужно передать им и
попросить привязать. Это стоит выяснить заранее: без этого шага
приложение в MAX не откроется, сколько бы всё остальное ни работало.

---

## 3. Проверить, что бэкенд отвечает снаружи

Фронтенд обращается к адресу из `frontend/api.js`. Сейчас это туннель:

```
https://hatching-landside-crown.ngrok-free.dev
```

Туннель живёт, пока на машине разработчика запущен агент и работают
контейнеры. Для показа этого достаточно, для сдачи — нет: жюри проверяют
решение после дедлайна, и компьютер к тому времени должен быть либо
включён, либо заменён постоянным хостингом.

При переезде меняется одна строка — `BASE_URL` в `frontend/api.js`, — и
перерегистрируется вебхук.

---

## 4. Перед каждым показом

```bash
docker compose up -d
```

```bash
ngrok http 8000
```

Проверка, что снаружи всё живо:

```bash
curl https://hatching-landside-crown.ngrok-free.dev/health
```

Ожидается `{"status":"ok", ... "bot_configured":true, "webhook_secret_set":true}`.

Если адрес туннеля сменился, подписку на события нужно оформить заново:

```bash
docker compose run --rm backend python -m scripts.setup_webhook
```

## Чего не хватит для календаря

Календарь и новости строятся на датах этапов, а в справочнике олимпиад
дат пока нет — только названия, уровни, классы и описания.

Сейчас даты есть у 20 олимпиад из старой выгрузки парсера, и календарь
показывает только их. Как только даты появятся в основном файле,
календарь наполнится сам: разбор дат, точность, статусы этапов и
правила планирования уже написаны и покрыты тестами.

Так что на вопрос «когда начинать пилить календарь» ответ такой: со
стороны бэкенда он готов, ему нужны данные.
