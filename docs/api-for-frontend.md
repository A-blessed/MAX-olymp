# API для фронтенда

Всё, что нужно, чтобы начать работать с бэкендом. Код бэкенда читать не
требуется.

## Адрес

```
https://hatching-landside-crown.ngrok-free.dev
```

Это туннель к машине разработчика: он живёт, пока запущен агент ngrok.
Ближе к сдаче адрес сменится на постоянный — меняться будет только он,
пути и форматы останутся прежними.

Живая схема со всеми полями и возможностью подёргать эндпоинты:
`/docs` по тому же адресу.

## Два обязательных заголовка

```
Authorization: tma <window.WebApp.initData>
ngrok-skip-browser-warning: true
```

**`Authorization`** — строка запуска, которую MAX отдаёт мини-приложению.
Берётся из `window.WebApp.initData` и передаётся **декодированной ровно
один раз**. Бэкенд проверяет её подпись на каждом запросе: без неё придёт
`401`. Идентификатор пользователя сервер берёт только отсюда, поэтому
слать `user_id` в теле запроса не нужно — он будет проигнорирован.

**`ngrok-skip-browser-warning`** — временный, только пока адрес туннельный.
Значение любое. Без него ngrok на бесплатном тарифе отдаёт браузеру
HTML-страницу с предупреждением вместо JSON, и запрос падает на разборе
ответа. После переезда на постоянный хостинг заголовок можно убрать, но
он безвреден и на обычном сервере.

## Заготовка запроса

```js
const API = "https://hatching-landside-crown.ngrok-free.dev";

async function api(path, options = {}) {
  const response = await fetch(`${API}${path}`, {
    ...options,
    headers: {
      "Authorization": `tma ${window.WebApp.initData}`,
      "ngrok-skip-browser-warning": "true",
      ...options.headers,
    },
  });

  if (response.status === 401) {
    const { detail } = await response.json();
    // Строка запуска протухла — мини-приложение нужно переоткрыть,
    // а не показывать пользователю ошибку.
    if (detail?.code === "expired") {
      window.WebApp.close();
      return;
    }
    throw new Error("Не авторизован");
  }

  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}
```

## Эндпоинты

### `GET /api/me`

Профиль текущего пользователя. Хороший первый запрос: проверяет всю
цепочку авторизации целиком.

### `GET /api/catalog/olympiads`

Список олимпиад.

| Параметр | Значения | По умолчанию |
|---|---|---|
| `q` | поиск по названию | — |
| `subject_id` | фильтр по предмету | — |
| `level` | 1, 2 или 3 | — |
| `sort` | `urgency`, `name`, `level` | `urgency` |
| `limit` | 1–200 | 50 |
| `offset` | сдвиг для пагинации | 0 |

Ответ: `{ items, total, limit, offset }`.

### `GET /api/catalog/olympiads/{id}`

Одна олимпиада со всеми этапами. `404`, если такой нет.

## Правило про даты — важное

Источник знает точную дату не всегда. Из 97 этапов у 65 известен день, у
32 — только месяц и год. Поэтому каждый этап приходит так:

```json
{
  "name": "Финальный этап",
  "kind": "final",
  "starts_on": "2027-03-01",
  "start_precision": "month",
  "days_until_start": null,
  "plannable": false,
  "raw_date_range": "мар 2027",
  "status": "upcoming"
}
```

**Если `days_until_start` равен `null` — таймер показывать нельзя.**
Вместо него выводится `raw_date_range` как есть: «мар 2027». Поле
`starts_on` в этом случае содержит первое число месяца — оно нужно
только для сортировки, показывать его пользователю нельзя.

**Если `plannable` равен `false`** — этап нельзя поставить в календарь по
дням: конкретной даты у него нет.

Для этапов с точным днём приходит число дней и `plannable: true` —
таймер и календарь работают как обычно.

| Поле | Значения |
|---|---|
| `kind` | `registration`, `qualifying`, `final`, `other` |
| `status` | `upcoming`, `active`, `finished`, `unknown` |
| `start_precision` | `day`, `month`, `null` |

`kind` определяется по названию этапа и является предположением.
`other` означает «определить не удалось» — таких сейчас 10 из 97, для
них лучше показывать название как есть, без ярлыка типа.

## Ошибки

Ошибка приходит в поле `detail`, у ошибок авторизации — с кодом:

| Код | Что случилось | Что делать |
|---|---|---|
| `expired` | строка запуска устарела | переоткрыть мини-приложение |
| `bad_signature` | подпись не совпала | проверить, что `initData` не изменён |
| `not_url_decoded` | строка не декодирована | декодировать ровно один раз |
| `bot_token_missing` | не настроен сервер | написать бэкендеру |

## Чего пока нет

Поля `subject_id`, `level`, `summary`, `official_url` приходят как `null`
— источник их не отдаёт, команда решает, откуда брать. Структура ответа
из-за этого не изменится.

Пользовательская часть — «Мои олимпиады», прогресс по этапам, календарь,
настройки — в работе. Эндпоинты появятся следом.
